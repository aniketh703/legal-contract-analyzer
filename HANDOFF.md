## Goal

Build an end-to-end **Legal Contract Analyzer** that:
1. Accepts an Indian commercial contract (PDF or TXT)
2. Segments it into individual clauses
3. Classifies each clause by type (Termination, NonCompete, etc.) and risk level (HIGH / MEDIUM / LOW)
4. Retrieves the relevant sections from the **Indian Contract Act 1872** knowledge base
5. Generates an HTML risk report with plain-English explanations and recommended actions

## Things That Changed (vs. original plan)

1. **Generator is template-based, not LLM-based** — decided against Claude API to keep the project self-contained, offline, and reproducible. Templates are statute-aware and vary based on retrieved sections.

2. **Curator rewritten** — original curator capped at 50 clauses with 2 per file. Rewrote with 3 extraction patterns (numbered blocks, quoted text, keyword proximity) and per-type targeting. Reached 212 clauses.

3. **Label Studio annotation skipped** — user chose to bypass. Classifier is validated against scraped labels only (not human-verified). Accuracy numbers are indicative, not final.

4. **Retriever uses 3-layer hybrid** — original plan was FAISS only. Added statute map (guaranteed section lookup per clause type) and BM25. Key finding: BM25 alone gets 23% Hit@5; statute map + BM25 gets 100%.

5. **Flask app had `/demo` and `/report` routes added** — needed for in-browser testing since the preview tool couldn't navigate via form submission timeout.

6. **`launch.json` has 3 servers** — Flask app (5000), Label Studio (8080), HTTP report preview (8000).

7. **P0/P1 hardening (May 2026)** — Retriever KB cache + FAISS graceful degradation; pinned `requirements.txt` + GitHub Actions pytest; legal disclaimer in UI/reports/JSON; expanded `_STATUTE_MAP` (22+ types); optional PDF OCR; `GET /health`; production WSGI note in README.

## Architecture (Simple)

```
User uploads contract (PDF / TXT)
        │
        ▼
  segmenter.py        → splits into clause dicts
        │
        ▼
  classifier.py       → adds clause_type + risk_level
  (keyword rules      → uses Indian Kanoon data to validate)
  + InLegalBERT
  embedding fallback)
        │
        ▼
  retriever.py        → adds retrieved_sections from ICA 1872 KB
  (statute map        → FAISS index of 185 ICA sections
  + FAISS + BM25
  + RRF fusion)
        │
        ▼
  generator.py        → builds HTML report
  (template-based,
  statute-aware)
        │
        ▼
  Flask app           → serves report at /analyse (POST)
```

### Two data sources — what each is for

| Source | Used for |
|--------|---------|
| **Indian Kanoon JSONs** | Training/evaluation data — 212 clause examples to validate the classifier |
| **Indian Contract Act 1872 PDF** | Knowledge base — 185 legal sections retrieved when explaining risk to the user |
